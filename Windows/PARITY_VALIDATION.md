# Windows macOS機能反映・検証記録（2026-09-21）

対象はIwashiScope 1.0.1 / Windows build 48（ファイルバージョン1.0.1.48）です。
macOS build 44までの変更を参照し、NucBox_G10のWindows 11 x64上でビルド・検証しました。
公開リリース、appcast更新、Gitのcommit/pushは実施していません。

## 反映内容

- CIE 248:2022のCIECAM16順変換・Q/M/h逆変換をC#に移植。初期値をCIECAM16とし、順応なし・Bradfordとの切り替えを実装。
- 反射率と光源SPDの共通範囲を5 nm間隔で積分し、D50基準も同じ波長範囲で再計算。保存された元の測定Labは変更しない。
- 光源未選択でも左のD50基準パッチを表示し、右に「光源を選択してください」、色差に「—」を表示。
- 「色順応」タイトル、計算条件、モデル計算エラー、sRGB範囲外の注意表示。
- 実用範囲・縦軸自動を全モードの初期値に設定。実用範囲はグラフ表示に適用し、見え方計算の積分範囲は変更しない。
- 日付グループを縦に配置し、各日付内のカードを折り返し表示。開閉状態はモードごとに保持。手動のカード順は保持。
- 選択履歴・日付単位の削除確認。対象IDとモードを確定し、ユーザー定義光源に登録中の履歴は削除しない。
- 反射光の日付書き出しは`YYYY-MM-DD.ase`、内部にも同名のASEグループを作成。単体・複数選択の右クリック、ドラッグでも拡張子は一つ。
- 環境光・発光の日付書き出しは日付フォルダへ、ドラッグ書き出しと同じスペクトル・CRI・TM-30 PNGを出力。既存ファイルを上書きしない。
- マンセル行と区切り線をLab図の下へ移し、ラベルを通常の文字色に。RGBの列見出し・数値は右揃えを維持。
- 更新されたmacOSアイコン資産からWindowsの9サイズPNG/ICOを再生成。

## 計算条件

macOSと同じく、標準観測者はCIE 1931 2°、標準積分範囲は380–730 nm、5 nm間隔です。
白Y=100、LA=20 cd/m²、背景Yb=20、平均的な周辺条件（F=1、c=0.69、Nc=1）を使用します。
選択光源下の試料から得たQ/M/hをD50の逆変換へ渡します。元試料の彩度・明るさを固定する方式ではありません。
理想白輝度100 cd/m²に相当する想定条件であり、実際の観察環境やディスプレイの測定値ではありません。
UV・蛍光、経時順応、周囲が別光源の場合、ディスプレイの表示限界は再現対象外です。

## 検証結果

- .NET SDK 10.0.300、Release / win-x64 / self-containedでアプリのビルド成功。警告0、エラー0。
- xUnit: 234件成功、失敗0、スキップ0。
- 独立したColour 0.4.7由来の11組のCIECAM16参照値をJ/Q/C/M/s/hの絶対差1e-8以内で照合し、逆変換も確認。
- 50種の同梱CIE光源、D50同士の一致、暖色白の残色、SPDの振幅不変性、同じ白色度でSPDが異なるケースを確認。
- 日付ASEのバイナリ構造・Lab特色値・並び順、全モードの削除範囲と保護、環境光・発光の日付出力とドラッグ出力の一致を確認。

- 光源未選択→光源A、方式3種のUIバインディング、日付・カード右クリックメニューの有効状態を確認。WPFバインディングエラー0。
- 1640 pxと1280 px幅の反射光比較、および環境光・発光のCRI/TM-30縦配置を画像で確認。
- 共通ArgyllCMSソースからWindows spotreadをビルドし、JSON Lines / 仮想スペクトル再計算テスト成功。
- WinSparkleは公式最新安定版0.9.4。完成したDLLのバージョン・NuGetとのSHA-256一致・ネイティブロード・利用する10個のexportを確認。
